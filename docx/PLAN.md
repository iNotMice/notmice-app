## 1. Цель фазы 2

К код-фризу 10.10 должен работать не бутафорский, а реальный конвейер данных — чтобы 16.10 подавать заявку с живым пайплайном.

Сквозной сценарий (DoD):

1. Пользователь создаёт псевдонимный аккаунт и один раз получает BIP-39 seed-фразу.
2. Загружает PDF/скан анализов.
3. Сервер в RAM считает SHA-256, извлекает маркеры, файл уничтожается.
4. Человек проверяет и правит цифры, затем подтверждает.
5. Система считает PhenoAge (исследовательский индекс, не медуслуга).
6. При включённом тумблере публичности обезличенные строки видны в `/api/v1/dataset` и CC0-выгрузке.

Текущий фронт на `notmice.ai.studio` — витрина на фикстурах из `src/data/phenoAgeData.ts`. Его не выкидываем: подключаем к backend.

## 2. Архитектура

```text
React/Vite SPA (фаза 1, уже есть)
        HTTPS
FastAPI (Python 3.12, async)
        SQLAlchemy 2.0 + Alembic
        PostgreSQL 16
        Claude Vision или Gemini — только серверно, ключ в env
```

Чистая архитектура backend (из `TECHNICAL_ARCHITECTURE.md`, без изменений):

```text
app/
├── core/          # config.py (pydantic-settings), logging.py, deps.py
├── domain/        # Pydantic v2, Enum, PII-валидаторы
├── repositories/  # SQLAlchemy async, без бизнес-логики
├── services/      # парсинг, LOINC, PhenoAge, экспорт
├── api/           # FastAPI-роутеры: валидация входа + вызов сервисов
├── migrations/    # Alembic
└── tests/         # pytest
```

Правило: роутер не знает про БД; репозиторий не знает про HTTP; сервис не знает ни про то, ни про другое.

Качество: ruff (zero warnings), mypy `--strict`, pytest, structlog, Google-style docstrings, секреты только через `.env` + pydantic-settings. Лицензии: код AGPL-3.0, словари CC-BY-4.0, экспорт датасета CC0.

Docker Compose: `api` / `postgres` / `proxy`.

### 2.1. Приватность (формулировка для кода, сайта и заявки)

| Что | Статус |
| :--- | :--- |
| Оригинал файла (PDF/фото) | Никогда не пишется на диск, только RAM, уничтожается сразу после подтверждения |
| SHA-256 хеш оригинала | Хранится в provenance — настоящий SHA-256 |
| Подтверждённые значения биомаркеров | В Postgres с согласия, привязка к псевдонимному ID, не к ФИО |
| Имя, дата рождения, номер пациента | Не собираются. PII-валидаторы отсекают на входе и на выходе |
| Публичный агрегат (opt-in) | `/api/v1/dataset` только для профилей с явно включённой публичностью |

Сайт и заявка говорят: *оригиналы документов не хранятся; структурированные значения хранятся с согласия; для исследовательского и коммерческого переиспользования обезличенных агрегатов.* Слоган «Zero Cloud Retention» с лендинга снимается.

## 3. API-контракт и схема БД

| Метод | Путь | Что делает |
| :--- | :--- | :--- |
| POST | `/api/v1/accounts` | Псевдонимный участник, BIP-39 фраза один раз; в БД только argon2id-хеш |
| POST | `/api/v1/uploads/extract` | PDF/скан в RAM → SHA-256 → pdfplumber или Vision LLM → JSON маркеров → файл уничтожается |
| POST | `/api/v1/uploads/confirm` | Подтверждённые значения + provenance в Postgres |
| GET | `/api/v1/dataset` | Read-only, rate-limit по IP, только opt-in строки, CSV/Parquet + datasheet |
| GET | `/api/v1/profiles/{id}/timeseries` | Временной ряд биомаркеров одного публичного профиля |
| GET | `/healthz` | Проверка БД, обязательна по DoD модуля 1 |

Таблицы минимум: `users`, `lab_results`, `biomarkers`, `provenance`, `share_settings`.

`UploadSession` из старого плана не входит в минимум ТЗ фазы 2 — не плодим таблицу без нужды; сессия извлечения живёт в памяти/во временном токене ответа extract, на диск не садится.

`pgvector` закладывается в схему под семантический поиск по публикациям (Phase 0), в MVP не используется.

## 7. Definition of Done к 10.10

MVP фазы 2 готов, если:

- пользователь регистрируется по настоящей BIP-39 seed-фразе;
- загружает PDF или изображение;
- сервер извлекает маркеры (не пресет Quest);
- человек подтверждает или правит значения;
- считается PhenoAge с дисклеймером;
- при opt-in данные видны в публичном API и CC0-выгрузке;
- оригинал не пишется на диск;
- provenance содержит настоящий SHA-256, лабораторию, дату забора, версию парсера, факт подтверждения;
- `/healthz` и CI зелёные;
- на лендинге нет утверждений про IPFS, ZK, WASM-OCR и Zero Cloud Retention, если они не реализованы.
